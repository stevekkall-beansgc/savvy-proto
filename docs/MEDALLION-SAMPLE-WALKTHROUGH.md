## Shared assessment, basis and rounding policy

These are explicit fictional policy settings carried in the API document and
result manifest, not hardcoded product exceptions:

- Preserve exact rational intermediate accruals. Sum client daily accrual per
  account/fee-component/currency/service-period, then assess once with half-up USD
  cent rounding. Signed ties round away from zero.
- Case A compensation references **exact unrounded daily earned-client-fee
  accrual**, with that day's selected share. Sum per account/recipient/compensation
  component/currency/service-period, then round the account-period amount once.
  Rounded invoice amounts and display allocations are not its input basis.
- The guarantee uses the sum of assessed/rounded fee-share compensation; coverage
  uses the resulting minor-unit obligation and evidenced available rights. The
  firm's fee-minus-compensation difference is a residual, not an independently
  rounded percentage that could break conservation.
- Fixed/per-unit components assess monthly. The named cap uses assessed charges;
  the receipt-qualified rebate uses confirmed source receipt cents, rounded once
  per firm/component/currency/service-period. Netting uses assessed charge/credit
  cents. Every component reference declares its basis classification.
- If detailed displays allocate an assessed period amount, use largest remainder,
  descending fractional remainder then canonical date/account/component ID ties.
  These conserved display allocations do not feed compensation calculations.
  A reversal negates the original assessed amount/allocations exactly.
- Intermediate child values, terminal assessed charge/credit outputs and summary
  values have distinct graph roles. Only the designated additive outputs enter a
  rollup; a capped group and its children are never all summed.

Other supported settings can be chosen through policy APIs and must have their
own reviewed vectors. No unspecified rounding/calendar/basis survives publication.

Required cent-boundary vectors (dollars, separate from the large golden cases):

| Exact input | Expected assessed/display outcome |
|---|---|
| Three daily accruals $0.005 each | Period $0.015 assesses $0.02, not $0.03; stable daily display $0.01/$0.01/$0.00. |
| Three daily accruals $0.004 each | Period $0.012 assesses $0.01; stable display $0.01/$0.00/$0.00. |
| Exact fee accrual $0.015 and constant 80% share | Exact-share basis $0.012 assesses $0.01. Substituting assessed client fee $0.02 would yield $0.02 share and must fail the Case A basis assertion. |
| One assessed $0.05 obligation allocated equally | Stable recipients receive $0.03/$0.02, conserving $0.05; do not independently round both allocations to $0.03. |
| Signed ties and reversal | +$0.005→+$0.01; −$0.005→−$0.01. Reversal of original $0.03/$0.02 is exactly −$0.03/−$0.02. |
| Shuffled/replayed delivery order | Same assessed amounts and allocation ties; separate currencies never share a residual pool. |

causes its headline amount to remain unchanged.

## Internal replay and acceptance checklist

- Original bytes → normalized versioned facts → same-engine policy binding →
  immutable detailed results → selected hourly/daily totals → external figures.
- Replayed duplicate deliveries preserve arrival history but produce no extra fee,
  receipt, rebate, invoice or coverage application.
- Every unchanged hourly publication selects the same logical economic results.
- Exact September 10/11/20/21 boundaries, missing signup/day, ambiguity, stale
  source, mismatched scope/currency and unsupported policy block affected outputs.
- A missing network receipt keeps rebate pending; received evidence enables it;
  reversal creates an adjustment, not a rewritten source or fictional refund.
- Cedar's late correction changes fee/share/floor components exactly as above.
- One-time event duplicates, conflicting payloads and late approvals obey the
  contract; guarantee inclusion produces the two distinct bonus outcomes above.
- Payment requests, pending/unallocated evidence and wrong-direction payments do
  not reduce payable. Valid $500 application reduces it to $1,800; linked reversal
  restores $2,300 with compensation unchanged. Credit is distinct from cash refund.
- A sealed prior statement survives a post hoc event; new statement lines reconcile
  to selected results and payment applications without duplicating old amounts.
- Invalid graph cycles, units, hidden defaults, conflicting groups and unapproved
  policy versions are rejected by the common API/interpreter.
- No UI, dbt model or product branch computes an independent monetary answer.
- Every displayed number has a readable basis and appropriate source freshness;
  internal users can expand exact evidence. External users cannot fetch raw
  internal data merely by selecting a different experience/product.
