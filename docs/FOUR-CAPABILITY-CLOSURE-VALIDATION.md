# Four-capability closure evidence

This closes the enumerated synthetic prototype cases in
`FOUR-CAPABILITY-CLOSURE.md`. The earlier invoice foundation alone did not do so.
The single Economics::Engine, API policy changes, Savvy native billing ownership
and mocked Campfire/CLM boundaries remain invariant.

| Scope | Implemented proof |
|---|---|
| Both products | Shared client, Product and Finance routes; native invoices, corrections, cash/recognition evidence and earnings/payables for both cases. |
| Commercial composition | Daily accrual, average-daily and ending/prior-period valuation, bands, dated/targeted rates, fixed/usage/time, approved one-time inputs, floors/caps and typed primitive graphs. |
| Advance/arrears lifecycle | Known prior-period valuation permits an advance claim; membership termination produces an exact unearned credit and independently evidenced prepaid refund. Unfinished arrears service cannot be invoiced. |

| Cash and refund lifecycle | Exact confirmed source/version, parties, currency, available cash, concurrent allocation, reversals, refund reservations/cancellation and independent refund evidence. Revised sources create a review exception rather than rewrite history. |

| Representative book | 200 independently scoped groups execute through queued evaluations; client results remain paged. This is a bounded synthetic workload, not a production throughput claim. |
| Mental model | Three-page architecture names actual Rails classes, PostgreSQL queue/storage and dbt projections. Both executed product examples link to native claim/cash/accounting/worker references. The minimal retained household graph is separately labelled. |

Read-only acceptance runs the legacy presentation, shared billing and lifecycle
browser suites, including 320/390px layouts and source/worker drilldowns. Mutating
browser checks run only against the disposable mounted API and exercise cash
application/reversal, mock accounting package preparation and API-only average-
daily policy authoring. Domain suites run serially against the guarded test DB.
Page reads never price, seed or publish. dbt keeps claim, accrual, cash and accounting
grains distinct and validates independent source/native lineage.

The implementation remains USD-only and bounded per request/group. Live provider
connectors, production authentication, external object storage, advisor hierarchy,
MCP/WebMCP, real agreements and live Campfire/CLM remain deferred. The generic graph
accepts supported typed operators, not arbitrary executable contract code. A new
primitive requires engine development; supported commercial compositions and values
are API data. Approved monetary loan/expense inputs are not a claim of real loan
servicing or equity valuation.
